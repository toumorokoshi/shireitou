# Agents View

Requirements for the shireitou agents view: a cross-platform Flutter app for
starting, monitoring, steering, and reviewing coding-agent sessions served by
[Agent Host Protocol](agent-host-protocol-client.md) hosts. The UX draws on the
GitHub Agents view and Cursor's Agents Window. Research and sources are in
[docs/research/agents-view-research.md](../docs/research/agents-view-research.md).

Priority: **P0** = MVP, **P1** = next, **P2** = later. Each requirement names
the AHP feature that backs it, where one exists.

### Worktree grouping

The folder key is the session's first `workingDirectories` URI, normalized
(trailing slash removed, `file://` decoded). It falls back to
`SessionSummary`/`SessionMetadata.project` when no working directory is set.
Rules:

- Two worktrees of the same repo, such as `~/src/app` and
  `~/src/app-worktrees/fix-login`, appear as **two separate folders**.
- On multi-host setups, the same path on different hosts is two folders
  (the key includes the host).
- A folder header shows "folder [repo]" and an attention dot (no
  counts, AV-092). Its "+" button (on hover with a pointer) starts a
  new session in that folder.
- Folders are sorted by their most recently modified session. Empty folders
  are hidden.
- Grouping is a pure function `(List<SessionSummary>) -> List<FolderGroup>`
  with unit tests covering the worktree cases.

Status (2026-10-16): implemented as `groupHostSessions` in
`app/lib/src/session_list/folder_grouping.dart`, keyed by host and folder,
with the folder "+" button. Sessions with no folder are listed in the
"Chats" section (`chatSessions`) instead of a "No folder" group. AHP has
no repo or branch fields; the label is "folder [project]"
(`workspaceLabel`) when the host's `project` has a display name, and the
header's tooltip adds the repository (when it is not the folder), the
branch from `_meta.git.branchName` (VS Code's agent host convention) and
the full path; pi reports neither, so its folders show the folder name
only.

### Sidebar tree

The left-hand session list (AV-012, AV-025, AV-028, AV-092, AV-093)
follows the [reference UI](../design/reference/agents-window.md). Hosts
are not a level of it: every open host's sessions are merged into the
same sections.

- **Header:** "Sessions", a small "New ⌘N" button (Ctrl+N off Apple
  platforms), a filter icon, a search icon and a "…" menu.
  - The filter icon opens a menu of the filters (Active, Needs
    attention with its count, Done, Archived, All) and the sorts (most
    recent, oldest, needs attention first), with the current ones
    checked. The icon is filled while a filter other than Active is on.
  - The search icon (and Cmd/Ctrl+K) shows the search field under the
    header, focused; its close button or Escape clears and hides it. It
    stays shown while it holds a query.
  - The "…" menu has "Select" (starts multi-select), "Add host…",
    "Disconnect" (the narrowed host, else every host), then one submenu
    per open host, labelled with the host and its status or error: "Show
    only this host" (with several hosts; narrows the list, and again
    shows every host), Retry and Remove for a host that is not
    connected, and "Editor settings…" (AV-015). The icon has a
    dot while a host has failed.
- **Sections,** top to bottom, each left out when empty:
  - **Pinned** (AV-028): the pinned sessions of every host, in the order
    they were pinned. A pinned session is listed here and not in its
    section (a folder holding only pinned sessions is not shown).
  - **Chats:** sessions with no working directory or project, of every
    host, in the sort order.
  - **One section per workspace folder** (the AV-025 folders, one per
    exact working directory on one host), labelled "folder [project]"
    with a folder icon. The same path on two hosts is two sections; with
    several hosts open, the header shows the host's label after the name.
    The tooltip on the name shows the repository, branch and full path.
- **Section headers** are an icon and text, with no counts: a small dot
  when a session in the section needs attention, and a chevron while
  collapsed. A tap collapses or expands the section. A folder's header
  shows a "+" on hover (always on compact layouts) that starts a session
  in that folder on that host.
- **Session rows** (AV-093) have two lines. The first is a small status
  dot and the title in regular weight, truncated. The second is a small
  folder icon, "folder [project]", the host's label when several hosts
  are open, the run label (AV-045), and the relative time ("10 hrs
  ago"), joined by " · ". Rows show no status chips or change stats.
  - While a session is working (`InProgress`, or an open chat's active
    turn before the catalogue catches up), the dot is a small running-colour
    spinner (`SessionStatusLeading`, `session_status_indicator.dart`); with
    reduced motion it is a static sync icon and the tooltip says "Working".
    Otherwise the dot's colour comes from the `SessionStatus` bitset with
    masks, never equality: needs input, then working, then error, then unread,
    else idle (`dotBadgeFor`), coloured with the theme's status tokens
    (`statusDotColor`, AV-090). Screen readers hear the status after the
    title.
  - Hovering (or focusing) a row with a pointer shows a pin icon and a
    "Mark as done" (archive, AV-024) icon on its right; mark done shows a
    snackbar with Undo that goes away after the default 4 s. An archived
    row shows "Unarchive" instead.
  - Resting the pointer on a row for 500 ms shows a card: the title in
    bold, " · agent · workspace", and under it a folder icon and
    "Workspace · full path".
  - The selected row has a subtle filled background with rounded
    corners. The row menu (right-click, long-press), swipe to archive,
    multi-select and screen reader actions stay as before.
- Opening a session (a click, a notification, Alt+↓/↑) expands the
  section that lists it. The collapsed sections and folders are kept on
  this device (`sidebar_collapsed`: `pinned`, `chats` and folder ids), so
  they stay collapsed after a restart.
- **Reordering folders:** a folder header is dragged onto another folder
  header (of any host) and takes its place, moving with its sessions.
  With a pointer the drag starts from the row (grab cursor, and a drag
  handle on hover or keyboard focus that opens "Move up" and "Move
  down"); on touch it starts after a long press. The target row shows a
  line above or below it where the folder will go. Right-click on a
  folder header, the handle, and the header's screen reader actions
  offer "Move up" and "Move down". The order is kept on this device
  (`folder_order`, a list of `FolderGroup.id`s, `'host|path'`).
- **Folder order:** folders the user moved come first, in the order
  they were placed, overriding the sort; folders never placed (a new
  working directory) follow in the sort order. Moving a folder places
  every shown folder, so what is shown stays put apart from the move.
  Orders saved when folders were ordered per host are read as one list,
  so each host's placed folders keep their relative order.
- Filters, search, sort, narrowing to a host and multi-select apply to
  every section. With no rows the list says "No sessions yet." or "No
  sessions match.". Next and previous session (Alt+↓/↑) and "Select
  all" follow the list order: Pinned, Chats, then the folders.
- **Density:** with a pointer (medium and wide layouts) section headers
  are 28 px (semibold) and session rows 56 px (title at 13 px, details at
  12 px), as measured in the reference screenshot. On
  compact layouts headers are at least 48 px and session rows 52 px for
  touch.
- The rows are built by pure functions: `splitPinned` in
  `app/lib/src/session_list/pinned_sessions.dart` takes the pinned
  sessions out of the shown ones; `chatSessions`, `sessionPlace`,
  `hostLabelsOf`, `sidebarRows` (the sections, skipping collapsed ones)
  and `revealSession` are in `app/lib/src/session_list/session_tree.dart`;
  `orderFolders` and `movedFolder` in
  `app/lib/src/session_list/folder_order.dart` apply and change the
  user's folder order; `dotBadgeFor` and `statusDotColor` are in
  `status_badges.dart`.

Status (2026-10-16): implemented. Hosts that are remembered but not open
are listed on the "Add host…" page (Recent hosts). Pinned sessions cannot
be reordered by drag. The reference's "Automations", "+N more" and
"Customizations" footer are not built.

**Copying a reply (AV-071)** follows VS Code's chat "Copy" action
(`workbench.action.chat.copyItem` in the response footer; checked in
its source, 2026-10-19). It copies the response, not the user's
message, as markdown: markdown parts as written, each tool call's
past-tense message (and its error) as a paragraph of its own, errors and
notes; reasoning, input requests and edits are left out. Links that only
resolve on the host (absolute paths, `file:` and other non-web schemes)
are replaced by their label as inline code, so a paste elsewhere does
not leak local paths; `http`, `https`, `mailto` and relative links are
kept. The icon turns into a check with the tooltip "Copied" for 1.2 s,
and "Copied to clipboard" is announced.

## Todos, plans, PR links, parallel runs and notifications

Findings of 2026-10-16 (AHP 1.0.0 and its main branch, VS Code's agent
host, pi-agent-host-protocol), which settle how these features work:

- **Todos and plans (AV-070, AV-046):** AHP's response parts are
  markdown, content refs, tool calls, reasoning, system notifications,
  input requests and errors; none carries a todo list or plan. Agents
  keep their list with a tool whose input is the whole list, and hosts
  pass it through as an ordinary tool call: Claude's `TodoWrite`
  (`todos[]` of `content`, `activeForm`, `status`), the Copilot CLI's
  `update_todo` (a markdown checklist), VS Code's `manage_todo_list`
  (`todoList[]` of `title`, `status`) and Codex's `update_plan`
  (`plan[]` of `step`, `status`, plus `explanation`). The client
  recognizes these by tool name (`todo_list.dart`) and renders them; the
  newest call is the current list. Plan mode is a session setting
  (`mode: plan` in VS Code's hosts); the plan is markdown, and the
  review that follows is an input request with a single-select question
  (described options, `allowFreeformInput`). VS Code adds a non-standard
  `planReview` object and `_meta.purpose` to that request; they are not
  in the schema, so the generated types drop them and the question alone
  is shown.
- **PR and branch (AV-105):** AHP has no field. VS Code's agent host
  publishes the branch in `_meta.git` (`branchName`, `githubOwner`,
  `githubRepo`, ...) and the pull request of the session's branch in
  `_meta["copilot.githubReferences"]` (entries with `referenceType: "pr"`,
  `url`, `number`, `title`, `state` and `relations`; the one with
  `headBranch` is the branch's PR), on both the session state and the
  catalogue summary. The client reads only that entry, and only when its
  URL is a GitHub pull request URL. A changeset operation's external
  follow-up (for example after "Create pull request") is opened in the
  browser (AV-103).
- **Parallel runs (AV-045):** AHP has no linked sessions, so the client
  keeps run groups on the device (`shared_preferences`, newest 50): the
  prompt, each run's host, session and agent/model label, and the
  picked run. Another client or device does not see the group, only the
  sessions. Up to five runs per prompt, on one host and folder.
- **Notifications (AV-121, AV-123):** AHP only delivers over a live
  socket, so the app posts local notifications while it runs, from
  catalogue status changes (`attention_events.dart`), and push while it
  is closed needs a relay ([push-relay.md](push-relay.md)). It is the
  user's turn when, between two catalogue snapshots, a session's status
  gains `InputNeeded` (needs input) or its turn ends (`InProgress`
  clears): failed when it ends with `Error`, otherwise finished; an
  `Error` that appears outside a turn also counts. This is a pure
  function of the two snapshots, so a host that keeps `Error` set into
  the next turn still gets that turn's result reported. All three events
  notify by default. Permission is asked for at start (desktop, mobile
  and the browser), and again from the bell menu while refused. Only
  the session on screen is quiet, and only while the window has focus.
  The app also plays a chime with those notifications (once per
  catalogue change, however many sessions changed), whether or not the
  system allows notifications, and then posts them silent; mobile apps
  chime only in the foreground. "Play a sound" in the bell menu turns
  it off.

## Out of scope (initially)

- Running agents locally inside the app. shireitou is a client; hosts run the
  agents.
- Managing cloud environments, secrets, network allowlists, or snapshots
  (Cursor and GitHub web-only admin features).
- Direct GitHub/GitLab API integration (PR merge, reviewers, CI status). PR
  actions come through host changeset operations instead.
- Automations/scheduled runs, remote desktop takeover, built-in browser, and
  the TCP and telemetry channels.
